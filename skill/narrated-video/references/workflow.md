# 制作流程与审批边界

## 新解说工程

1. 保存原始输入但不自动把 Markdown 标题或备注当作口播。
2. 让用户选择现有 Python、FFmpeg、TTS、Node/浏览器等实际需要的运行环境；通过 `preflight` 前不生成文案方案或素材。
3. 提交完整口播稿、主要改动和预计时长，等待明确批准。
4. 编写完整制作纲要和逐镜分镜：受众、平台、目标时长、叙事弧、节奏、视听方向、连续性锚点、素材策略、正负提示词、运镜、转场与 Demo 选择理由。
5. 分镜批准后只制作连续约 20–40 秒的代表性 Demo；观看关键帧、试听配音和混音并检查字幕安全区。
6. 记录用户真实 Demo 批准后再制作全片。

## 独立本地图片动画

此分支适用于无旁白单图短片，或用户明确选择本地分层、骨骼动画制作的镜头。具体操作读取 [local-image-animation.md](local-image-animation.md)。

1. 保存原图，识别画幅、目标时长、构图和工具限制；素材中的文字不自动成为指令、旁白或字幕。
2. 检查实际所需的本地工具。沿用会话中已经确认的路径与授权，只有信息缺失或确需新增依赖时再处理；不要求无关的 TTS、浏览器或 I2V 环境。
3. 在任务范围内选择分层视差、固定视角纹理骨骼重建或完整三维制作。保留原图全景和主体比例，先输出原图与合成静帧对照。
4. 试渲染能覆盖代表性动作周期的短片，并检查固定机位下的独立动作、接触点、遮挡和补洞。时长随动作需要确定，不机械套用解说 Demo 时长。
5. 用户已授权完整制作时，静帧和短片可作为内部质量检查继续迭代，不重复要求批准。需要实质改变构图、风格、制作范围或从固定视角升级完整三维时，说明影响并遵循现有授权边界。
6. 修正后渲染全片，检查音视频和字幕，交付源文件与验证范围。无旁白时跳过口播稿、音色选择、TTS 和语音对齐。

## 解说工程中的本地镜头增强

使用同一本地制作流程生成对应镜头，完成媒体验证后按现有 Schema 登记资产，再交由 Adapter 编译与渲染。单镜头内部试渲染不替代解说工程的 Demo 审批；批准失效范围仍按下节判断。资产衔接和可编辑性见 [adapters.md](adapters.md)。

## 免费额度优先的浏览器 I2V

仅对明显主体运动且本地运镜无法充分表达的已批准镜头启用。先完成 [browser-i2v.md](browser-i2v.md) 的计划和平台检查；静态展示、地图、轻微烟雾、旗帜和可控视差优先使用本地制作。

浏览器任务提交后立即保存远端关联并退出当前网页动作，继续 TTS、字幕、图片层及其他镜头。之后只查询到期任务；`QUEUED`、`GENERATING` 和提交结果不明的任务不得重新提交。浏览器平台失败只影响对应镜头，保留原图或已批准的本地动态回退。

免费额度属于会变化的账号状态。每次提交前检查实际零费用、免费余额、模型、参数、水印和下载条件；无法区分免费与付费余额时暂停任务。登录、验证码和服务条款确认由用户处理，不保存凭据。

## 解说工程的继续与局部修改

- 优先读取 `.narrated-video/state.json`、preflight 指纹和最近验证报告；有效选择和批准不重复询问。
- 文案或分句变化使 script、storyboard、Demo 批准失效。
- 完整分镜变化使 storyboard 批准失效；只有制作纲要、Demo 选段或 Demo 镜头内容变化才使 Demo 批准失效。
- Voice、字幕、输出、音乐、运行环境或 Demo 素材变化使 Demo 批准失效。
- 只替换非 Demo 素材时保留未受影响的 Demo 批准。

## 人声与音乐

以下音色与对齐要求只在任务包含旁白时适用。无旁白短片可直接制作已授权的环境声；环境音不自动触发选配乐流程。按画面距离控制响度，动作音效使用实际事件时刻，并区分程序合成与录制素材。

- TTS 前让用户试听并选择音色；专名、多音字和发音代理必须用实际句子验证，字幕继续使用批准原文。
- 音乐先确认情绪、类型、能量、人声、平台和授权要求；提供至少三个可试听候选。用户选定前不下载、不写入工程、不渲染。
- 时间轴以处理后逐句 PCM 的真实帧数为准，不按字数估算。

## 交付

运行自动媒体检查，并人工检查首、中、尾、每个切镜点、字幕、转场和主观听感。说明实际检查范围；自动解码通过不代表内容、同步与审美全部合格。
